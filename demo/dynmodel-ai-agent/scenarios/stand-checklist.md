# Чек-лист стендов: Dynamic Model AI Agent в каждой теме

Ручная проверка на стендах 8091–8096: вход `admin` / `admin`, язык «Русский». Стенды и их запуск
описаны в [README](../README_ru.md).

Каждый кейс, кроме раздела 1, проходится на всей матрице:

| Колонка | Стенд | Порт | Тема | Цвет | Направление |
|---|---|---|---|---|---|
| A-L | `aura-light` | 8091 | Aura | светлая | LTR |
| A-D | `aura-dark` | 8092 | Aura | тёмная | LTR |
| L-L | `lumo-light` | 8093 | Lumo | светлая | LTR |
| L-D | `lumo-dark` | 8094 | Lumo | тёмная | LTR |
| RTL | `aura-rtl` | 8095 | Aura | светлая | RTL |

Отметки: ✅ прошло, ❌ упало (номер бага рядом), — неприменимо.

## 1. Режим вкладок (tabbedmode)

Только на стенде 8096 (`aura-light-tabbed`, Aura, светлая): режим вкладок есть лишь в нём.

| # | Шаги | Ожидаемый результат | 8096 |
|---|---|---|---|
| 1.1 | Открыть настройки динамической модели во вкладке, перейти в AI, получить результат, нажать «Применить» и подтвердить миграции | Меню обновилось сразу. В чате появилось сообщение «Изменения применены…», AI-сессия сброшена, чат остался | |
| 1.2 | Открыть настройки в двух вкладках. В первой сделать «Применить» | Сообщение о публикации только в первой вкладке. Во второй чат не изменился | |
| 1.3 | В настройках во вкладке запустить запрос и во время работы переключиться на другую вкладку и обратно | Блокировка редактора, прогресс и результат на месте. Редактор разблокирован после завершения | |
| 1.4 | Закрыть вкладку настроек, пока агент работает | Диалог подтверждения. «Отмена» оставляет вкладку, подтверждение закрывает без ошибок | |
| 1.5 | Закрыть вкладку настроек с открытым вопросом агента | Закрывается без диалога подтверждения | |

## 4. Ошибки и сообщения

| # | Шаги | Ожидаемый результат | A-L | A-D | L-L | L-D | RTL |
|---|---|---|---|---|---|---|---|
| 4.1 | В режиме «Код» испортить YAML и переключиться в AI | Предупреждение «Исправьте YAML в режиме «Код», прежде чем открывать AI.» Режим не меняется, запуск не начинается | | | | | |
| 4.2 | В модели опубликованный пункт меню поставлен перед пунктом, которого больше нет (например, удалённой сущности). Попросить добавить поле в другую сущность | Запрос выполняется: прежняя проблема модели не мешает новому изменению | | | | | |
| 4.3 | Попросить поле `first_name` рядом с `firstName` | Отказ с объяснением про одинаковую колонку | | | | | |
| 4.4 | Сущность с записями: попросить обязательное поле | Исполнимого плана с обязательным полем нет: агент объясняет ограничение или сообщает «Не удалось подготовить допустимый план» | | | | | |
| 4.5 | Вручную сделать заполненное необязательное поле обязательным | Проверка не мешает. Если есть пустые записи, блокирующая находка | | | | | |
