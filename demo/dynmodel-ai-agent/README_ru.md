# 🤖 Dynamic Model AI Agent — демо-стенды B2B CRM

🌐 Языки: [English](README.md) | [Русский](README_ru.md)

Опишите обычными словами, какие данные нужны, — агент подготовит сущности, поля, экраны и пункты
меню, вы проверите его план и опубликуете результат одной кнопкой, без кода и без перевыпуска
приложения. Dynamic Model — аддон Jmix Premium, который позволяет работающему приложению обзаводиться
новыми сущностями и экранами; AI-агент управляет им из чата.

Эта ветка добавляет агента в B2B CRM и оформляет приложение как набор демо-стендов. Бизнес-пользователь
открывает **Администрирование → Настройки динамической модели**, переключает редактор в **AI** и
описывает изменение. Агент предлагает план, пользователь его подтверждает. Подтверждённый план меняет
только модель в редакторе; в работающее приложение ничего не попадает, пока пользователь не нажмёт
**Применить**. После этого новые экраны сразу появляются в меню и готовы к вводу данных.

> **Предварительная версия.** Агент — Dynamic Model AI Builder,
> [jmix-framework/jmix#5779](https://github.com/jmix-framework/jmix/issues/5779) — влит в `master` Jmix
> и выйдет в Jmix 3.1, который ещё не выпущен. До выпуска ветка собирается на Jmix и Jmix Premium
> `3.1.999-SNAPSHOT` из их веток `master`, поэтому для сборки нужен доступ на чтение к репозиторию
> Jmix Premium. Внутри команды Jmix стенды можно запустить и из готовых jar.

## ✨ Что показывает демо

- **На входе — обычные слова, на выходе — план, который можно проверить.** Один запрос создаёт две
  связанные сущности с полями, списком, карточкой и пунктами меню. План перечисляет каждое изменение
  до того, как что-то произойдёт; при наведении на поле видны его подписи на всех языках приложения.
- **Решает человек.** Пользователь может дополнить план в том же чате, подтвердить его, проверить
  результат в визуальном редакторе и опубликовать кнопкой **Применить** — или не публиковать вовсе.
  Агент сам ничего не публикует, а пока он работает, редактор заблокирован.
- **Каждый шаг на виду.** Шкала над чатом показывает этап — «Запрос», «План», «Подготовка», «Проверка»,
  «Применение», — а **Рабочая область** рядом с чатом показывает текущий план или изменения модели и
  замечания. В ответах есть ссылки на снимки только для чтения: план, подготовленные и применённые
  изменения, шаги выполнения.
- **AI и ручная правка работают с одной моделью.** Добавьте поле в режиме **Визуальный**, поправьте
  подпись в режиме **Код**, затем спросите агента — он видит неопубликованные ручные изменения.
- **Точечные изменения.** «Поставь дату следующего контакта перед суммой» превращается в план из
  одного перемещения поля.
- **Настоящие экраны и данные.** Опубликованные сущности сразу готовы к работе: обязательные поля
  проверяются, ссылки показывают названия, даты и суммы сохраняются с правильными типами.
- **Модель растёт дальше.** Новый разговор добавляет справочник, ссылку на него, коллекцию участников
  и перестановку пунктов меню — и сохраняет существующие поля, экраны и данные.
- **Понятные границы.** Агент отказывается читать бизнес-данные («посчитай сумму всех сделок клиента»)
  и отказывается от небезопасных изменений опубликованной модели (смена типа поля).

## 💻 Стенды

Стенды отличаются оформлением, чтобы агента можно было показать в каждой теме;
`aura-dark` к тому же может работать на Claude, а `aura-light-tabbed` открывает экраны во вкладках.
У каждого стенда своя база, поэтому изменения на одном не видны на другом.

| Имя | Порт | Тема | Цвет | Направление | Модель |
|---|---|---|---|---|---|
| `aura-light` | 8091 | Aura | светлая | слева направо | DeepSeek v4.1 Flash |
| `aura-dark` | 8092 | Aura | тёмная | слева направо | Claude, если задан `ANTHROPIC_API_KEY`, иначе DeepSeek |
| `lumo-light` | 8093 | Lumo | светлая | слева направо | DeepSeek |
| `lumo-dark` | 8094 | Lumo | тёмная | слева направо | DeepSeek |
| `aura-rtl` | 8095 | Aura | светлая | справа налево | DeepSeek |
| `aura-light-tabbed` | 8096 | Aura, экраны во вкладках | светлая | слева направо | DeepSeek |

Адрес: `http://localhost:<порт>/b2b-crm/`, вход `admin` / `admin`.

## 🧰 Что нужно

- JDK 21 или новее: в `JAVA_HOME` или в `PATH` (именно JDK, не JRE: команда `stop` запускает
  `Shutdown.java` как исходный файл).
- Ключ [OpenRouter](https://openrouter.ai) в переменной окружения `OPENROUTER_API_KEY`. Без него стенды
  запускаются, но агент отвечает ошибкой вызова модели.
- По желанию — `ANTHROPIC_API_KEY`: с ним стенд `aura-dark` работает на `claude-sonnet-5`; другую модель
  Claude можно задать в `STAND_CLAUDE_MODEL`.
- Память: куча каждого стенда ограничена 768 МБ, так что на каждый запущенный стенд нужен примерно 1 ГБ
  свободной памяти.
- Свободные порты 8091–8096 (HTTP) и 9191–9196 (JMX). Стенды слушают только `127.0.0.1`; не открывайте
  эти порты наружу.
- Доступ на чтение к Jmix Premium для сборки.

## 🔨 Сборка

Ветка собирается на Jmix и Jmix Premium `3.1.999-SNAPSHOT`, которые вы публикуете сами из их веток
`master`: `mavenLocal()` стоит первым репозиторием в `settings.gradle` и `build.gradle`, поэтому тот, кто
работает с этой веткой, перед сборкой публикует оба репозитория в локальный Maven. Публикуйте их целиком:
открытый модуль `io.jmix`, которого нет локально, молча возьмётся из ночной сборки Jmix той же версии, а
она может отличаться от вашей копии; без premium-модуля сборка остановится.
Если в локальном Maven нет Gradle-плагина Jmix, сборка сразу остановится с сообщением
«Plugin [id: 'io.jmix', version: '3.1.999-SNAPSHOT'] was not found». На Windows вместо `./gradlew`
используйте `.\gradlew.bat`.

1. Склонируйте `jmix` и `jmix-premium` на ветке `master`, а `jmix-crm` — на ветке `50-dynmodel-ai-agent`:

   ```bash
   git clone -b master https://github.com/jmix-framework/jmix.git
   git clone -b master https://github.com/jmix-framework/jmix-premium.git   # нужен доступ
   git clone -b 50-dynmodel-ai-agent https://github.com/jmix-framework/jmix-crm.git
   ```

2. В `jmix`:

   ```bash
   ./gradlew publishToMavenLocal -x test -x javadoc \
       :jmix-build:publishToMavenLocal :jmix-gradle-plugin:publishToMavenLocal \
       :jmix-translations:publishToMavenLocal :jmix-templates:publishToMavenLocal
   ```

3. В `jmix-premium`:

   ```bash
   ./gradlew publishToMavenLocal -x test -x javadoc
   ```

4. В `jmix-crm`: `./gradlew bootJar`. Стенды запускают `build/libs/crm.jar`. После каждого обновления
   `jmix` или `jmix-premium` повторите шаги 2–3.

5. Только для стенда со вкладками — собрать ветку `50-dynmodel-ai-agent-tabbed` в соседнем worktree:

   ```bash
   git worktree add ../jmix-crm-tabbed 50-dynmodel-ai-agent-tabbed
   (cd ../jmix-crm-tabbed && ./gradlew bootJar)
   ```

   Скрипты стендов ищут `../jmix-crm-tabbed/build/libs/crm.jar`; чтобы взять jar из другого места,
   задайте `STAND_TABBED_JAR` (и `STAND_JAR` для остальных пяти). Если jar нет, его стенд пропускается.

Перед пересборкой остановите стенды: на Windows работающий jar не перезаписывается.

## 🚀 Запуск и остановка

Из этой папки (`demo/dynmodel-ai-agent`). macOS и Linux:

```bash
./stands.sh start                 # все шесть; первый старт около минуты
./stands.sh status
./stands.sh start aura-rtl        # один стенд
./stands.sh stop                  # все; или один: ./stands.sh stop lumo-dark
```

Windows, PowerShell:

```powershell
.\stands.ps1 start
.\stands.ps1 status
.\stands.ps1 stop
```

Если PowerShell не даёт запустить скрипт: `powershell -ExecutionPolicy Bypass -File .\stands.ps1 start`.

**Останавливайте стенды только командой `stop`.** Она просит приложение завершиться и сохранить базу.
Если убить процесс (`kill -9`, диспетчер задач, перезагрузка), база стенда при следующем запуске не
восстановится, и стенд зависнет на старте с сообщением «Waiting for changelog lock». Тогда помогает
только сброс.

**Сброс стенда:** остановите его и удалите папку `instances/<имя>`. При следующем запуске он создаст
чистую базу с демо-данными CRM. Лог стенда — `instances/<имя>/application.log`.

## 💡 Что стоит знать заранее

- Агент сам ничего не публикует: после подтверждения плана изменения лежат в редакторе, публикует
  человек кнопкой **Применить** (в режиме AI она внизу рабочей области).
- Агент работает с сущностями динамической модели. В Jmix 3.1 он не умеет впервые расширять
  существующую сущность приложения, создавать для неё экраны и пункты меню, а также создавать
  поля-перечисления и вычисляемые поля.
- Стенды поднимают лимиты агента в `application.properties`: до 24 шагов в плане и четыре минуты на
  один запрос. Планы демо больше, чем позволяют значения по умолчанию.
- Позицию поля («поставь дату перед суммой») лучше просить отдельным запросом. Внутри большого запроса
  на создание она иногда приводит к тому, что план не удаётся подготовить.
- В длинном разговоре модель может начать путаться: однажды после 14 запросов она решила, что
  существующей сущности нет. Перед новой задачей очистите диалог кнопкой с ластиком
  (**Очистить диалог**); неопубликованные изменения модели останутся в редакторе, если не отметить их
  отмену в подтверждении.
- Модель DeepSeek Flash иногда отвечает по-разному на один и тот же запрос. Если ответ странный,
  повторите запрос.
- После обновления страницы режим AI не восстанавливается из адреса, его нужно снова выбрать
  переключателем.
- Агент записывает каждый разговор и запуск в базу, но экрана для них нет. Разработчики могут
  посмотреть сущности `dmagent_*` в Инспекторе сущностей по адресу `/b2b-crm/datatl/entity-inspector`.

## 🧩 Что в ветке

По сравнению с `main`:

- **Агент в CRM** — стартеры Dynamic Model и AI-чата вместе с `io.jmix.dynmodel:jmix-dynmodel-ai-starter`
  и `jmix-dynmodel-ai-flowui-starter`, их changelog-файлы Liquibase (у агента —
  `/io/jmix/dynmodelai/liquibase/changelog.xml`), пункт меню **Настройки динамической модели**, лимиты
  агента (свойства `jmix.dynmodel.ai.*`) и его собственное подключение к модели: OpenAI-совместимая
  чат-модель на OpenRouter (`DynamicModelAgentConfiguration`, свойства `crm.dynmodel.*`), независимая от
  AI-ассистента CRM. `DynamicModelAgentIntegrationTest` проверяет, что агент и его экран настроек на месте
  рядом с CRM.
- **Сборка** — Jmix `3.1.999-SNAPSHOT` с локальным Maven первым репозиторием для Gradle-плагина и
  библиотек (`settings.gradle`, `build.gradle`), production-режим Vaadin с production-бандлом,
  пересобранным под Vaadin 25.3.
- **Переключатели стендов** — тема, цвет и направление из системных свойств `stand.theme`,
  `stand.color`, `stand.direction` (`CRMApplication`), стили CRM под Lumo (`themes/lumo`) и прямое
  подключение Claude для одного стенда (`StandAnthropicConfiguration`, `spring-ai-anthropic`).
- **Совместимость с Jmix 3.1** — мелкие правки API, собственный маршрут главного экрана, чтобы закрытие
  экрана возвращало на «Главную», и инициализация динамических атрибутов после старта приложения.
- **Запуск стендов** — `stands.sh`, `stands.ps1` и `Shutdown.java` (корректная остановка через JMX).

Ветка `50-dynmodel-ai-agent-tabbed` идёт следом за этой и добавляет аддон Tabbed Mode и главный экран
со вкладками.

## 🎤 Ветка demo/ai-app

`demo/ai-app` дополняет эту ветку для доклада «AI × Jmix»: AI-ассистент CRM, ИИ-сгенерированный JPQL в
отчётах и агент Dynamic Model на одном стенде.

- **Сборка** — шаги 2–3 раздела [Сборка](#-сборка), затем в `jmix-crm` на ветке `demo/ai-app` (а не на
  `50-dynmodel-ai-agent` из шага 1):

  ```bash
  demo/dynmodel-ai-agent/stands.sh stop     # сначала: запущенные стенды читают ~/demo-jars/crm.jar
  ./gradlew bootJar && mkdir -p ~/demo-jars
  cp build/libs/crm.jar ~/demo-jars/crm.jar.new && mv ~/demo-jars/crm.jar.new ~/demo-jars/crm.jar
  cd demo/dynmodel-ai-agent && STAND_JAR="$HOME/demo-jars/crm.jar" ./stands.sh start aura-light
  ```

  Перед заменой jar остановите стенды и дождитесь `stopped` в `demo/dynmodel-ai-agent/stands.sh status`: запущенный стенд
  подгружает классы из своего jar по мере надобности, и jar, перезаписанный под ним, ломает стенд.
  Копируйте в `crm.jar.new` и переименовывайте `mv` поверх `crm.jar`: переименование атомарно,
  недописанный jar никто не увидит. Копия вне репозитория не меняется, когда рабочая копия переключается
  на другую ветку или `build/` очищается. `STAND_JAR` указывайте при каждом старте (и для `aura-dark`):
  без него `stands.sh` запускает `build/libs/crm.jar` из репозитория.
- **JPQL в логе** — `logging.level.io.jmix.aitools.dataload=DEBUG`: в `instances/<имя>/application.log`
  стенда видны запрос, который написал ассистент (`executeQuery(jpql=…)`), и row-level условия, которые
  AI Tools добавили к нему (`Access conditions applied`).
- **Персональные данные закрыты для AI** — `Contact.phone` и `Contact.email` помечены `@ExcludeFromAi`
  (AI Tools, Jmix 3.1). Собственные каналы CRM к модели тоже её соблюдают: клиент, добавленный в контекст
  чата, приходит без них, отчёт Client 360, запущенный ассистентом, их не выводит. В приложении они видны.
- **Row-level права в запросах значений** — роль Manager может читать `User.id`, который сравнивают
  условия Only My Accounts; без этого запрос с join от `alice` (AI Tools или полоса с ИИ-сгенерированным
  JPQL) отклоняется.
- **Отчёты с ИИ-сгенерированным JPQL** — в `demo/reports/ai-jpql-reports.zip` два отчёта: «Выручка
  клиентов (AI JPQL)» (сохранённый запрос, параметры `fromDate` и `toDate` типа «Дата», шаблон «Таблица»)
  и «Выручка клиентов (живая генерация)» (та же полоса без запроса, для кнопки «Сгенерировать запрос»).
  Отчёты живут в базе стенда: архив импортируется в **Администрирование → Отчёты → Отчёты →
  Импортировать** после каждого сброса. Сохранённый запрос написан вручную в том формате, в котором его
  хранит генератор; чтобы показать формулировку модели, сгенерируйте его заново с ключом. Повторный
  импорт обновляет отчёты с теми же id и затирает сохранённое на стенде, поэтому после сохранения
  перегенерированного запроса экспортируйте оба отчёта, замените архив и запустите
  `AiJpqlReportsArchiveTest`: он импортирует архив и запускает отчёт под admin и под alice.
- **Пользователи** — `admin` / `admin` видит всех 30 клиентов, `alice` / `alice` (Manager + Only My
  Accounts) — своих 13.
